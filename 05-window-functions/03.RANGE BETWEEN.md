# 03. RANGE BETWEEN

> **Core idea:** `ROWS` physical row position ko track karta hai, while `RANGE` `ORDER BY` column ki **value** ko track karta hai.

---

## 1. RANGE BETWEEN kya hai?

`RANGE BETWEEN` SQL window function ke andar **window frame type** hai.

Example:

```sql
SUM(salary) OVER (
    ORDER BY salary
    RANGE BETWEEN 2 PRECEDING AND CURRENT ROW
)
```

Yahan:

- `SUM()` = window function
- `OVER(...)` = window definition
- `ORDER BY salary` = rows ko logical order deta hai
- `RANGE BETWEEN ...` = **window frame define karta hai**

### Important

> **RANGE ek window function nahi hai. RANGE ek window frame type hai.**

---

# 2. ROWS vs RANGE — sabse important difference

### ROWS

`ROWS` physical row position dekhta hai.

Socho school ki line:

```text
1. Rahul
2. Amit
3. Neha
4. Priya
5. Sam
```

Agar teacher bole:

> "Current student ke 2 students pehle aur current student tak dekho."

Teacher **position** count karega.

```text
2 PRECEDING → CURRENT ROW
```

---

### RANGE

`RANGE` `ORDER BY` column ki **value** dekhta hai.

Socho students ki marks list:

```text
100
100
101
102
102
103
```

Agar current value `102` hai aur frame hai:

```text
RANGE BETWEEN 1 PRECEDING AND CURRENT ROW
```

to:

```text
102 - 1 = 101

Value range = 101 → 102
```

Ab SQL value check karega:

```text
100  ❌
100  ❌
101  ✅
102  ✅
102  ✅
103  ❌
```

Total:

```text
3 rows
```

### Memory trick

```text
ROWS
→ "Kitni physical positions?"

RANGE
→ "Kaunsi ORDER BY values?"
```

---

# 3. RANGE ka fixed solving algorithm

Har RANGE question ko isi order me solve karo:

```text
1. Current ORDER BY value
          ↓
2. Lower boundary calculate karo
          ↓
3. Upper boundary calculate karo
          ↓
4. Exact VALUE RANGE likho
          ↓
5. Har row ki ORDER BY value check karo
          ↓
6. Matching values ki ALL rows include karo
   (including peers)
```

### Golden rule

> **First VALUE RANGE decide karo, then ROWS collect karo.**

---

# 4. PRECEDING

`n PRECEDING` ka matlab:

```text
Current value - n
```

Example:

```text
Current value = 103
```

Frame:

```text
RANGE BETWEEN 2 PRECEDING AND CURRENT ROW
```

Calculation:

```text
103 - 2 = 101
```

So:

```text
Value range = 101 → 103
```

---

# 5. FOLLOWING

`n FOLLOWING` ka matlab:

```text
Current value + n
```

Example:

```text
Current value = 102
```

Frame:

```text
RANGE BETWEEN CURRENT ROW AND 2 FOLLOWING
```

Calculation:

```text
102 + 2 = 104
```

So:

```text
Value range = 102 → 104
```

---

# 7. Duplicate values and Peer Groups

Ye RANGE ka sabse important concept hai.

Suppose:

```text
salary

100
100
101
102
102
103
```

Current value:

```text
102
```

Frame:

```sql
RANGE BETWEEN 1 PRECEDING AND CURRENT ROW
```

Value range:

```text
102 - 1 = 101

101 → 102
```

Now:

```text
101  ✅
102  ✅
102  ✅
```

Dono `102` rows include hongi.

Why?

Because same `ORDER BY` value wali rows **peer group** hain.

### Golden rule

> **Range ke andar value aayi → us value ki ALL rows include.**

> **Range ke bahar value → uski ALL peer rows exclude.**

---

# 8. Peer Group boundary ko expand nahi karta

Important trap:

```text
100
100
101
101
102
102
103
```

Current = `102`

Frame:

```sql
RANGE BETWEEN 1 PRECEDING AND CURRENT ROW
```

Calculate:

```text
102 - 1 = 101

Value range = 101 → 102
```

Included:

```text
101
101
102
102
```

`100` peers exist karte hain, but:

```text
100 < 101
```

So they are outside the range.

### Important

> **Peer group boundary ko expand nahi karta.**

Pehle range decide hota hai:

```text
101 → 102
```

Phir us range ke andar values ki saari peer rows collect hoti hain.

# 10. CURRENT ROW in RANGE

Ye bahut important distinction hai.

Suppose:

```text
100
101
102
102
102
103
```

Current physical row = middle `102`

Frame:

```sql
RANGE BETWEEN CURRENT ROW AND CURRENT ROW
```

Current ORDER BY value:

```text
102
```

So value range:

```text
102 → 102
```

Matching rows:

```text
102
102
102
```

Total:

```text
3 rows
```

### Why?

Because RANGE ka `CURRENT ROW` physical row ko target nahi karta.

It uses the **current ORDER BY value**.

### Compare with ROWS

```sql
ROWS BETWEEN CURRENT ROW AND CURRENT ROW
```

would select:

```text
only the physical current row
```

= `1 row`

### Memory

```text
ROWS CURRENT ROW
→ current physical row

RANGE CURRENT ROW
→ current ORDER BY value + peers
```


Important:

> Peer row physical current row se pehle ho ya baad me, agar uski `ORDER BY` value same hai to RANGE me include ho sakti hai.

# 18. The most important comparison

| ROWS | RANGE |
|---|---|
| Physical row position | ORDER BY value |
| Positional frame | Value-based frame |
| "How many rows?" | "Which values?" |
| Duplicates don't automatically expand frame | Duplicate peers can expand frame |
| Current row = physical current row | Current row = current ORDER BY value + peers |

### One-line memory trick

> **ROWS counts positions; RANGE compares values.**

# 19. Default frame in MySQL

Consider:

```sql
SUM(salary) OVER (
    ORDER BY salary
)
```

No explicit `ROWS` or `RANGE` is written.

For MySQL, with an `ORDER BY`, the default frame is effectively:

```sql
RANGE BETWEEN UNBOUNDED PRECEDING
          AND CURRENT ROW
```

So:

```sql
SUM(salary) OVER (
    ORDER BY salary
)
```

can be understood as:

```sql
SUM(salary) OVER (
    ORDER BY salary
    RANGE BETWEEN UNBOUNDED PRECEDING
              AND CURRENT ROW
)
```

### Example

```text
salary

100
100
101
102
102
```

Current value = `102`

Default RANGE frame:

```text
100 → 102
```

Included:

```text
100
100
101
102
102
```

Total:

```text
5 rows
```

### Important correction

Do not memorize:

> "Database automatically decides ROWS or RANGE."

Instead:

> **When frame is omitted, use the database's documented default frame.**

For MySQL in this case:

```text
ORDER BY + no explicit frame
→ RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
```

# 20. Why default RANGE matters

With duplicate `ORDER BY` values, default RANGE can include the whole peer group.

Example:

```text
salary
------
100
100
101
102
102
```

A running total using:

```sql
SUM(salary) OVER (
    ORDER BY salary
)
```

may behave like:

```text
100 → 200
101 → 301
102 → 505
102 → 505
```

Both `102` rows can receive the same cumulative result because they belong to the same peer group under the default RANGE frame.

---

# 21. If you want physical row-by-row behavior

If the requirement is:

> "I want the running total to follow physical row-by-row positions, even when ORDER BY values are duplicated."

Explicitly use:

```sql
ROWS BETWEEN UNBOUNDED PRECEDING
         AND CURRENT ROW
```

Example:

```sql
SUM(salary) OVER (
    ORDER BY salary, employee_id
    ROWS BETWEEN UNBOUNDED PRECEDING
             AND CURRENT ROW
)
```

Here `ROWS` tracks physical row position within the specified ordering.

# 22. Tie-breaker and deterministic ordering

Suppose:

```text
salary | employee_id
-------|------------
100    | 1
100    | 2
101    | 3
102    | 4
102    | 5
```

If you only use:

```sql
ORDER BY salary
```

then rows with the same salary are tied.

A unique column such as:

```sql
ORDER BY salary, employee_id
```

provides a deterministic tie-breaker.

### Why useful?

It gives SQL a precise ordering:

```text
100 / 1
100 / 2
101 / 3
102 / 4
102 / 5
```

### Interview answer

> **A unique tie-breaker makes the ordering deterministic when the primary ORDER BY column has duplicate values.**

# 23. Common traps

## Trap 1: RANGE = number of rows

Wrong:

> "2 PRECEDING means 2 physical rows."

That's `ROWS` thinking.

For RANGE:

```text
Current value = 103

2 PRECEDING
→ 103 - 2 = 101
```

So the value range begins at `101`.

---

## Trap 2: Peer group expands the boundary

Wrong:

> "100 is a peer, so RANGE 101–102 will also include 100."

No.

First determine:

```text
101 → 102
```

Then include all rows whose values are inside that range.

---

## Trap 3: RANGE CURRENT ROW = one row

Wrong.

```sql
RANGE BETWEEN CURRENT ROW AND CURRENT ROW
```

with:

```text
102
102
102
```

can include all three `102` rows.

---

## Trap 4: ROWS and RANGE are always different

Wrong.

With unique ORDER BY values, they can return the same rows for a particular frame.

But their semantics remain different.

---

## Trap 5: UNBOUNDED PRECEDING = first row's value

Not exactly.

Better:

> **Start of the partition.**

# 25. RANGE mental model

Think of RANGE like a **number ruler**.

Current value:

```text
        102
         ↓
98  99  100  101  102  103  104
```

If frame says:

```text
2 PRECEDING → 1 FOLLOWING
```

then:

```text
102 - 2 = 100
102 + 1 = 103

         ↓↓↓↓↓↓↓↓↓
98  99 [100 101 102 103] 104
```

Now SQL asks:

> "Which rows have ORDER BY values inside this highlighted value range?"

Every matching row comes in.

If a value has duplicates:

```text
100
100
```

both come in.

# 27. Interview-ready answers

### What is RANGE BETWEEN?

> `RANGE BETWEEN` is a window frame type that defines a frame based on the `ORDER BY` values rather than physical row positions.

### ROWS vs RANGE?

> `ROWS` uses physical row positions, while `RANGE` uses `ORDER BY` values.

### Why does RANGE include duplicate rows?

> Because rows with the same `ORDER BY` value form a peer group, and all matching peer rows within the value range are included.

### What does RANGE CURRENT ROW mean?

> It refers to the current `ORDER BY` value and its peer rows, not just the physical current row.

### What does n PRECEDING mean in RANGE?

> It creates a lower value boundary by subtracting `n` from the current `ORDER BY` value.

### What does n FOLLOWING mean?

> It creates an upper value boundary by adding `n` to the current `ORDER BY` value.

### What does UNBOUNDED PRECEDING mean?

> Start the frame from the beginning of the partition.

### What does UNBOUNDED FOLLOWING mean?

> Extend the frame to the end of the partition.

# 29. Final self-test

Before answering any RANGE question, ask yourself:

```text
□ What is the current ORDER BY value?
□ What is the lower boundary?
□ What is the upper boundary?
□ What is the exact value range?
□ Which ORDER BY values fall inside it?
□ Are there duplicate peer rows?
□ How many rows are finally included?
```

If you can answer these seven questions, you can solve most `RANGE BETWEEN` problems confidently.
